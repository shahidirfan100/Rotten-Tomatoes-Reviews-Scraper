# API Discovery — Rotten Tomatoes Reviews Scraper

Re-run from scratch after Rotten Tomatoes changed its review data flow. This file is the
first place to read when the actor starts failing, because the site has an internal JSON
review API that is now gated, plus stable server-rendered review data that always works.

## Summary of what changed

The old actor fetched reviews from the internal JSON endpoint
`/napi/rtcf/v1/movies/{emsId}/reviews` using a browser. That endpoint is now protected by
Akamai Bot Manager and returns `401 Unauthorized` with an empty body for every non-browser
client — including a headless browser, a headful browser, US residential/datacenter proxies,
and a US-hosted reader service. Rotten Tomatoes' own front-end calls it and also receives
`401`, so the public review page currently renders **no** server-side review list.

The stable, unprotected source is the **movie page HTML** (`/m/{slug}`), which server-renders
a review sample even without JavaScript or cookies. This is what third-party wrappers
(`crawlora`, `vee3`, `parse.bot`) now return and mark as `public_page_derived: true`.

## Selected source A — server-rendered movie page (primary, always available)

- Endpoint: `https://www.rottentomatoes.com/m/{slug}`
- Method: `GET`
- Auth: none
- Works with impit `browser: 'chrome'` (also `firefox`) using plain HTTP, no cookies required
- Provides:
  - `script[data-json="reviewsData"]` → JSON with audience reviews: `reviews[]`,
    `audienceScore`, `criticsScore`, `reviewsUrl`, `title`, `vanity`, `viewMoreText`
  - `<review-card-critic>` web components (critic review sample) with slots
    `name`, `publication`, `timestamp`, `rating`, `review`, `review-link`
  - `<review-card-audience>` web components (audience review sample) with slots
    `name`, `timestamp`, `rating`, `review`
  - `script[data-json="vanity"]` → `emsId`, `value` (slug), `title`, `lifecycleWindow`
  - `script[data-json="mediaScorecard"]` → Tomatometer + Popcornmeter scores/sentiment
  - `#critics-consensus` → critics consensus text
- Pagination: none for the public sample (a fixed featured set per title)
- Field count: 25+ useful fields after mapping

## Selected source B — internal reviews JSON API (best-effort, currently gated)

- Endpoint: `https://www.rottentomatoes.com/napi/rtcf/v1/movies/{emsId}/reviews`
- Method: `GET`
- Query: `after`, `before` (cursors), `pageCount`, `topOnly`, `type` (`critic`|`audience`),
  `verified`
- Pagination: cursor-based via `pageInfo.hasNextPage`, `pageInfo.endCursor`,
  `pageInfo.startCursor`
- Current status: `401 Unauthorized` (empty body) for all non-browser clients.
  A single replay of a freshly captured browser session returned `200` once, then `401`
  again — the Akamai sensor token (`hgdtnmcjyr-*` request headers + `eXr91Jra` cookie) is
  session/IP-bound and one-time, and is generated by JavaScript that impit cannot execute.
- The actor still attempts this endpoint first with the page session (cookie jar) so it
  auto-heals the moment Rotten Tomatoes restores anonymous API access, then falls back to
  source A.

## Required request context (what actually works)

- impit default Chrome profile, `useHeaderGenerator` not needed (impit generates a coherent
  TLS + header profile automatically).
- No cookies or tokens are required for the public page.
- `Referer: https://www.rottentomatoes.com/m/{slug}` and `Accept: application/json` are sent
  for the best-effort API attempt.
- Proxy is optional. `proxyConfiguration` is still honoured for request routing.
- HTTP/2 is used by impit's Chrome profile and works for the page.

## Why the API returns 401 (diagnosis checklist)

1. `GET /napi/rtcf/v1/movies/{emsId}/reviews?...` → `401`, `content-length: 0`,
   response header `set-cookie: eXr91Jra=...` (Akamai sensor seed) plus an `akamai-grn` header.
2. Adding `Accept`, `Referer`, `Origin`, `X-Requested-With`, `sec-fetch-*` and US-geo cookies
   does not change the result.
3. A real browser sends Akamai sensor headers (`hgdtnmcjyr-a`..`-z`) and still receives `401`
   from headless, so the sensor is rejected for automation.
4. No `akam/*` sensor script is referenced in the initial HTML — it is injected by JavaScript
   after load, so it cannot be reproduced over plain HTTP.
5. Conclusion: the endpoint cannot be used reliably from impit. Use the movie page.

## Notes

- `emsId` is read from `script[data-json="vanity"]` (`.emsId`) or `reviewsData.vanity.emsId`.
- Slug can redirect (`/m/oppenheimer` → no cards; `/m/oppenheimer_2023` → cards). Prefer the
  canonical slug from the RT search/URL the user supplied.
- The public sample is a small featured set per title (typically 6 critic + 6 audience). This
  is a Rotten Tomatoes product decision, not a parser limitation.
